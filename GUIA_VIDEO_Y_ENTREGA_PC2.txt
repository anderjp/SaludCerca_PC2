Guía para preparar la entrega y grabar la exposición de SaludCerca PC2
Basada en la consigna del profesor y en el código revisado el 15/10/2026.

El proyecto tiene los nueve patrones exigidos. El objetivo es completar la entrega verificable y demostrar dominio del código. No se garantiza una nota: cada criterio vale 4 puntos y la sustentación la evalúa el profesor.

1. QUÉ FALTA SEGÚN LA RÚBRICA

Criterio 1: entorno, framework y bibliotecas (4 puntos).
Ya están Spring Boot, MVC, Thymeleaf, JPA/Hibernate, driver SQL, validación y logger. La aplicación se verificó con Java 21 y MariaDB de XAMPP. Mostrar el pom.xml y la separación model/repository/service/web/pattern. El Word y la PPT se ajustaron a Java 21 y a la fecha 16/10/2026. Probar la instalación desde una copia descargada del repositorio: iniciar-local.ps1 tiene rutas específicas de esta PC; para otra PC se necesita JDK 21, ejecutar el SQL en una base nueva, configurar MySQL y usar el wrapper Maven. El SQL no es una migración para importar repetidamente sobre tablas con datos.

Criterio 2: cinco patrones creacionales (4 puntos).
Están Singleton, Prototype, Factory Method, Abstract Factory y Builder. Deben verse funcionando, estar reflejados en UML y justificarse. El diagrama Abstract Factory del Word ya se ajustó al ancho de página. Corregir la referencia mutable entre Builder y Reporte: el reporte ya construido no debería cambiar al reutilizar el builder o modificar la lista expuesta.

Criterio 3: cuatro patrones estructurales (4 puntos).
Están Adapter, Facade, Decorator y Composite. Hay casos de uso en las pantallas. Corregir disponibilidad para que las citas canceladas no bloqueen turnos que se muestran libres y proteger las reservas simultáneas del mismo médico/horario. Explicar RENIEC, mensajes, pagos y enlaces de reunión como simulaciones de esta entrega.

Criterio 4: calidad de código, SOLID y repositorio (4 puntos).
El repositorio público https://github.com/anderjp/SaludCerca_PC2 ya permite consultar el código, el SQL, el wrapper Maven, el README y los documentos. La URL real se incorporó en Word 4.1 y diapositiva 1. Sincronizar las últimas correcciones de los documentos desde VS Code. Mantener código fuente ordenado, documentación y README reproducible. Mejorar la separación de la lógica de registro/reserva actualmente presente en PacienteController.

Criterio 5: sustentación y demo (4 puntos).
Se debe explicar y demostrar cada patrón, localizarlo en código y responder preguntas. La consigna establece 15 minutos de presentación/demo y 5 de preguntas. El video sirve de ensayo o evidencia; la consigna entregada no dice que sustituya la demo en vivo, por lo que esa sustitución depende de lo que haya indicado el profesor por otro medio.

Correcciones de documentos antes de grabar o entregar:
- Fecha de portada 16/10/2026 e índice real: corregidos y verificados en el informe de 18 páginas.
- Imágenes ajustadas al ancho útil sin deformarse: UML Abstract Factory y varias capturas se salen del área de página.

Si continúan fuera de esta entrega, declararlo claramente y no presentar esas funciones como terminadas. El 50% se sustenta con funcionalidades y casos de uso implementados frente a los pendientes, no con un porcentaje de líneas de código. Strategy y Observer son para una etapa posterior: no forman parte de los nueve patrones obligatorios de esta PC2.

2. QUÉ ES EL REPOSITORIO Y CÓMO ENTREGARLO

Un repositorio guarda el código y sus cambios. Git es la herramienta de versiones; GitHub es una plataforma donde puede alojarse el repositorio. El profesor necesita una URL desde la que pueda leer/descargar y ejecutar el proyecto. No es un requisito desplegar la web en un hosting público: localhost sirve para la demo y el repositorio sirve para entregar el código.

Ruta sencilla usando el sitio web de GitHub:
1) Crear/iniciar sesión en una cuenta de GitHub.
2) Usar New repository, nombre SaludCerca-PC2. Elegir público para acceso sin invitación o privado con acceso concedido al profesor. La consigna permite repositorio público o con acceso.
3) Crear el repositorio. Evitar generar otro README o .gitignore si se van a subir los que ya contiene el proyecto.
4) Usar Add file / Upload files (o el enlace para subir archivos existente en un repositorio vacío). Arrastrar carpetas conservando su estructura.
5) Subir src/, db/, .mvn/, pom.xml, mvnw, mvnw.cmd, README.md, .gitignore y .gitattributes. Agregar Word/PPT corregidos, por ejemplo en una carpeta docs/. No depender de iniciar-local.ps1 para otra computadora: contiene rutas locales.
6) No subir target/, .vscode/, .claude/, historiales internos ni contraseñas o claves reales. En una carga por navegador hay que omitir esos archivos manualmente; no asumir que .gitignore filtrará una selección arrastrada.
7) Guardar los cambios (commit) con un mensaje claro, por ejemplo: PC2: implementación de patrones y manual de ejecución. El historial debe reflejar cambios reales.
8) La subida web admite hasta 100 archivos por operación y 25 MiB por archivo. Si el total excede 100 archivos, subir las carpetas en varios lotes. No subir el video pesado como parte del código; entregarlo por el medio que haya solicitado el profesor.
9) Copiar la URL real, sustituir [usuario] en Word/PPT y verificar acceso desde otra sesión. Si es público, abrir en ventana privada; si es privado, comprobar con una cuenta autorizada.
10) Descargar el repositorio en otra carpeta y seguir el README. Debe compilar y funcionar sin depender de archivos personales fuera de esa copia, salvo los requisitos instalados (JDK y MySQL).

5. PREGUNTAS QUE DEBES PODER RESPONDER

¿Qué diferencia hay entre Factory Method y Abstract Factory?
Factory Method delega a subclases la creación de un producto: el canal Email/SMS. Abstract Factory produce una familia de productos relacionados: comprobante y leyenda.

¿Qué diferencia hay entre Adapter y Facade?
Adapter traduce una interfaz/formato incompatible; aquí la respuesta del proveedor simulado. Facade ofrece una operación sencilla que coordina varios subsistemas; aquí el agendamiento completo.

¿Dónde está el Singleton? ¿Por qué no basta una variable global?
En ConfiguracionApp, con constructor privado y acceso estático controlado. El diseño restringe la construcción y entrega la misma instancia. La demostración compara referencias, no simplemente que dos números impresos coincidan.

¿Cómo demuestras Prototype?
Crear dos clones desde la plantilla registrada, cambiar uno y verificar que el otro conserve los datos base; mostrar el endpoint o clonar() y el constructor de copia.

¿Dónde se ve Decorator?
En objetos CostoConsulta envueltos por decoradores de recargo, seguro e impuesto. Todos conservan la interfaz monto()/descripcion().

¿Por qué Composite y no solo una lista?
Porque un paquete puede contener servicios o paquetes anidados y el cliente usa la misma interfaz para ambos; el total se calcula recursivamente.

¿Dónde se usa Builder?
En ReporteService al configurar pasos opcionales y llamar construir(), que produce Reporte. No confundir un formulario con la implementación del patrón.

¿La validación RENIEC y los avisos son reales?
No. Son proveedores/canales simulados que permiten probar el diseño. El adaptador conserva el contrato para sustituir el proveedor en una integración futura.

¿El repositorio ejecuta la página por sí mismo?
No. Permite revisar y descargar el código. Se ejecuta siguiendo el README; una publicación en hosting sería una tarea adicional.

¿Qué porcentaje tienen completo?
Explicar el alcance verificable: reserva con validaciones y registro de pago/aviso, atención con plantilla e historial, panel/catálogo/reportes/configuración y los nueve patrones. Declarar los casos de uso pendientes. No inventar una medición de porcentaje por archivos o líneas.
